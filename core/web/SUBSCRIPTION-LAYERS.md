# 구독 층 (draft)

진행 중인 설계 초안이다. main에 머지하기 전에 구현을 읽어 `EXPR-EVAL.md`와
`LEAF-STORE-LAYOUT.md`에 반영하고 이 파일은 지운다. 큰 개념만 적고 세부는 구현하며 정한다.

## 용어

| 낱말 | 뜻 |
|---|---|
| 파생 구독 | 입력으로 값을 만들어 내는 구독. 입력은 leaf 또는 다른 파생 구독이다 |
| 결과 leaf | 파생 구독 트리의 뿌리가 만든 값이 `set`되는 leaf. 입력 leaf와 달리 vm이 런타임에 잡는다 |
| 통지 구독 | `notify` 단계에서 불리는 구독(코드의 `subscribe`, `TSubscriber`). 파생 구독은 `notify` 전 단계에서 돈다 |
| 입력 leaf | 변수가 놓인 leaf. 파생 구독이 읽는다 |

## 층

```
  DOM 바인딩        텍스트/속성 쓰기, @if/@for 분기 전환
       |  leafIndex를 구독한다 (통지 구독)
       v
  표현식 층         입력을 읽어 식을 세고, 결과 leaf에 set한다
       |  입력 leaf를 구독한다 (파생 구독)
       v
  구독 층           leaf마다 구독 함수 목록, notify, batch
       |
       v
  store             leaf에 값 쓰기/읽기 (set, get), alloc, free
```

DOM 바인딩은 표현식을 모른다. 변수 보간이든 식 보간이든 leafIndex 하나를 구독 층에 구독할
뿐이다. 식 보간은 표현식 층이 식을 만들 때 결과 leaf의 leafIndex를 돌려주고, DOM 바인딩은 그
leafIndex를 변수의 leaf와 똑같이 구독한다. 표현식 층은 구독 층과 store만 쓰고, 구독 층은
표현식을 모르며, store는 구독을 모른다.

```
  DOM 바인딩 -----------------> 구독 층 -> store
                                  ^
  표현식 층 ----------------------+
     (식을 만들면 결과 leaf의 leafIndex를 돌려준다)
```

## 구독 두 종류

| 종류 | 거는 쪽 | 거는 곳 | 도는 단계 | 하는 일 |
|---|---|---|---|---|
| 파생 구독 | 표현식 층 | 입력 leaf | `notify` 전 | 식을 다시 세어 결과 leaf에 `set`한다 |
| 통지 구독 | DOM 바인딩 | 입력 leaf 또는 결과 leaf | `notify` | leaf의 확정된 값을 DOM에 쓴다 |

통지 구독은 입력 leaf인지 결과 leaf인지 구별하지 않는다. 파생 구독이 모두 끝난 뒤에 통지
구독이 불리므로 중간 값이 DOM에 닿지 않는다.

## 파생 구독의 구조

파생 구독은 트리다. 아래 끝은 입력 leaf를 읽는 곳이고, 안쪽 노드는 파생 구독이며, 뿌리가 만든
값이 결과 leaf에 `set`된다.

- 결과 leaf는 다른 파생 구독의 입력이 되지 않는다. 파생 구독의 입력은 입력 leaf이거나 다른
  파생 구독이다. 결과 leaf에 파생 구독을 거는 것은 컴파일러가 막는다 - 결과 leaf는 소스에서
  이름을 붙일 수 없다.
- 파생값을 다른 파생 구독의 입력으로 쓰려면 구독 연쇄로 넘긴다. 파생 구독이 파생 구독을
  구독하고, 결과 leaf를 거치지 않는다.
- 하위 결과(`cache[3]`, `cache[7]` 같은 중간 값)는 leaf가 되지 않는다. 노드끼리 구독 연쇄로
  이어진다.
- leaf를 갖는 것은 통지 구독이 걸리는 뿌리 하나다. DOM 구독이 걸리려면 leafIndex가 있어야
  하기 때문이다.
- 노드를 공유하지 않는다. 같은 식을 두 번 보간하면 트리와 결과 leaf가 두 벌 생긴다.
- 선례: `IF_EXPR`은 이미 결과 leaf를 잡고 분기가 그것을 구독한다(`vm.ts`의 `bindExpr` 주석).
  보간 식으로 넓히는 셈이다.
