# 커밋 규칙

커밋은 **타이틀 한 줄만** 적는다. 본문(설명 단락)을 붙이지 않는다.

기준은 하나다: **타이틀만으로 작업 내용을 알 수 있게.** 한 줄에 안 담기면 제목을 늘이지 말고
커밋을 나눈다.

두 가지를 함께 지킨다.

- **서술투로 쓰지 않는다.** "~한다", "~하여 작성한다"로 늘이면 길이만 늘고 내용은 그대로다.
  명사로 끝낸다(`추출`, `변경`, `추가`, `제거`, `수정`).
- **무엇을 했는지가 있어야 한다.** 명사로 끝냈다고 끝난 게 아니다 - `해시맵으로`는 무엇을
  했는지가 없고, `해시맵으로 변경`은 있다.

대시 뒤는 **제목만으로 모를 것**(근거, 수치)을 담는다. 대시 뒤에도 위 두 규칙이 그대로 걸린다.
담을 게 없으면 대시째 뺀다 - 성능 개선의 수치처럼 있으면 좋은 것도 필수는 아니다.

아래 예시는 전부 가상이다.

| O | X | 이유 |
|---|---|---|
| `비슷한 로직의 코드 함수로 추출` | `계속 되풀이 되는 코드 조각들을 함수로 분리하여 작성한다` | 명사형 종결 위반 |
| `렉서가 주석 건너뛰도록 변경` | `렉서가 주석을 건너뛴다` | 명사형 종결 위반 |
| `상수풀 조회 해시맵으로 변경` | `상수풀 조회 해시맵으로` | 무엇을 했는지 없음 |
| `빈 배열 push 시 앵커 조회 실패 수정` | `빈 배열 push 앵커 못 찾는 문제` | 문제를 어쨌다는 건지 없음 |
| `빈 배열 push 시 앵커 조회 실패 수정` | `@for 관련 이슈 해결` | 무엇이 어떻게 없음 |
| `TEST.md 문서 5.1, 5.2 섹션 추가` | `TEST 문서 수정` | 무엇을 고쳤는지 없음 |
| `런타임 구독 해제 누락 수정` | `버그 수정` | 무슨 버그인지 없음 |
| `resmap 캐시 제거 - Blob URL 키 불일치로 캐시 미적중` | `resmap 캐시 제거 - Blob URL이라 매번 새 키가 되어 안 맞았다` | 대시 뒤 명사형 종결 위반 |
| `resmap 캐시 제거 - Blob URL 키 불일치로 캐시 미적중` | `resmap 캐시 제거 - Blob URL 키 불일치` | 불일치로 뭐가 됐는지 없음 |
| `렉서가 주석 건너뛰도록 변경` | `렉서가 주석 건너뛰도록 변경 - 주석을 건너뛴다` | 대시 뒤가 제목 되풀이 |
| `슬롯 파서에 기명 슬롯 순서 정규화 추가` | `슬롯 파서 고치고 테스트 추가하고 SYNTAX 갱신` | 여러 작업이 한 커밋에 |
| `qubb 인스펙터에 def 트리 패널 추가` | `qubb 인스펙터에 def 트리 패널 추가` + 본문 3문단 | 본문 금지 |

기능과 그 기능을 겨냥한 테스트는 **같은 커밋**이다 - 나누지 않는다.

설명하고 싶어지면 커밋이 큰 것이다. 본문을 붙이지 말고 나눈다.

```
1. qubb 인스펙터에 def 트리 패널 추가
2. 인스펙터 트리 노드 선택 시 opcode로 스크롤 추가
```

## 본문과 트레일러

- **본문을 붙이지 않는다.** 설명하고 싶어지면 커밋이 크다는 신호다 - 나눈다.
- **`Co-Authored-By` 트레일러를 넣지 않는다.**

**Why:** 히스토리를 제목만으로 훑을 수 있게 유지한다. 내용이 제목 한 줄에 안 담긴다는 건
커밋이 너무 크다는 신호라, 길이 제한이 곧 관심사 분리로 이어진다.

이 규칙은 **앞으로의 커밋**에 적용한다. 과거 커밋은 고치지 않는다.

## 커밋 전 `cargo fmt` (`.rs`를 만졌으면)

스테이징 전에 `cargo fmt`를 돌린다. 안 하면 그 파일이 rustfmt 기준에서 벗어난 채로 들어가고,
다음에 누가 fmt를 돌릴 때 무관한 diff가 섞인다. 저장소 전체는 2026-07-30에 fmt로 통일해 뒀으니
`cargo fmt --check`가 깨끗한 상태를 유지한다. `--check`로 확인만 하지 말고 **실제로 적용한다** -
줄바꿈 차이는 스타일 취향이 아니라 도구 기준이다.

**fmt가 고친 건 무관한 파일이라도 같이 커밋한다.** `cargo fmt`는 워크스페이스 전체를 돌므로
내가 안 만진 파일의 미적용분까지 잡힐 수 있다. 그걸 "내 변경 범위 밖"이라고 `git checkout`으로
되돌리지 않는다 - 포맷은 저장소 공통 규칙이고, 미적용분이 남아 있던 쪽이 원래 잘못된 상태다.
되돌리면 다음 사람이 같은 diff를 또 만난다. "인접 코드 건드리지 말 것"은 내 판단으로 하는
개선에 대한 것이지, 도구가 강제하는 포맷에는 적용되지 않는다.

## 커밋 분리

NEXT.md 갱신은 단독으로 커밋한다(CLAUDE.md).

타이틀 하나로 표현이 힘든 큰 변경은 작업 단위별로 나눈다. **전제조건: main이 아닌 피처
브랜치일 것.** 이때 나눈 중간 커밋은 각자 빌드/테스트를 통과하지 않아도 된다 - 파일 간
상호의존으로 단계마다 통과 상태를 만들기 어려운 변경(예: 컴파일러 슬롯 계약 <-> 런타임)도
논리 단위로 쪼갤 수 있다.

main에 직접 커밋할 땐 이 완화가 없다 - **커밋마다 온전해야 한다.**
